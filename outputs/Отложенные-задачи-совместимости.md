# Отложенные задачи совместимости

Дата фиксаци: 27 сентября 2026 года.

Эти задачи не блокируют основной этап — применение режима 12 FPS к готовой итоговой позе игрока. К ним нужно вернуться после выполнения основной задачи.

## 1. Лицо Just Expressions замирает во время эмоции

### Статус

Не исправлено. Версия `0.5.0-alpha.2` не решила проблему.

### Симптом

При запуске любой эмоции Emotecraft лицо остаётся в состоянии, которое было в момент активации. Моргание и движение глаз не продолжаются.

### Подтверждённая конфигурация

- `stepped_player_animations 0.5.0-alpha.2`;
- Fresh Animations 1.10.4;
- Just Expressions 1.2.1;
- FA Player Extension 1.1;
- compatibility add-on `FA+Player_Expressions-v1.2` отключён;
- EmoteBend отключён.

### Данные из лога 02:18

- Мод и нужные ресурспаки загрузились.
- Покомпонентное смешивание активировано для всех шести групп тела.
- Мод восстанавливает 362 EMF-части.
- Диагностическая строка `Just Expressions face branch detected` отсутствует.

### Вывод для будущего исправления

В runtime-модели EMF ветка лица не обнаруживается по полю `id == player_face`, хотя такой ID есть в файлах ресурспака. Простое расширение текущего фильтра не работает. Перед следующей попыткой нужно:

1. Добавить одноразовый дамп runtime-иерархии головы: класс, ID, имя в map и связи родитель/потомок.
2. Определить, встраивается ли `player_face.jpm` в другую ветку или переименовывается при сборке EMF-модели.
3. Отделять лицо от паузы по фактической runtime-иерархии, а не по предполагаемому ID из JPM-файла.

### Критерий готовности

Во время длительной эмоции глаза, зрачки, веки и брови продолжают анимироваться, а движение головы Emotecraft не ломается.

## 2. Универсальность для ETF/EMF-ресурспаков

### Статус

Запланировано, но не реализовано. Текущая гарантия распространяется только на проверенную связку FA Player Extension + Emotecraft + Just Expressions.

### Цель

Убрать жёсткую привязку к конкретным ID и структуре FA Player/Just Expressions и поддержать большинство паков, которые меняют модель, геометрию, мимику или анимации игрока через ETF/EMF.

### Планируемый подход

1. Автоматически снимать runtime-карту всех EMF-частей и их связей.
2. Определять функциональные группы по иерархии и фактическим каналам анимации, а не только по именам.
3. Добавить профили/адаптеры для типовых схем паков, если автоопределения недостаточно.
4. Безопасно отключать неподходящий адаптер вместо повреждения модели.
5. Создать матрицу тестов с несколькими популярными ETF/EMF-паками, включая Expressive Fresh Moves.

### Ограничение

«Большинство» не означает гарантию работы с любым будущим или нестандартным паком. Для неизвестных структур должен быть безопасный режим и понятная диагностика.

### Критерий готовности

Проверенные паки корректно сохраняют свою геометрию, мимику и анимации при одновременной работе с Emotecraft и режимом 12 FPS; неизвестные паки не вызывают крашей и грубых артефактов.
