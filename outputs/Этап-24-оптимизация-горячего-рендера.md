# Этап 24 — оптимизация горячего рендера

Версия: `0.16.0-alpha.1`

## Цель

Снизить процессорную нагрузку и давление на сборщик мусора без изменения внешнего вида, частоты кадров анимации и совместимости с EMF, Emotecraft и Flashback.

## Изменения

- Деревья частей обычных и EMF-моделей теперь собираются один раз на время жизни модели, а не несколько раз за каждый отрисованный кадр.
- Снимки поз переиспользуют уже созданные массивы и объекты. При новом 8/12/24/25-FPS-сэмпле обновляются только числовые поля трансформации.
- UV-сопоставление каждого сегмента согнутого EMF-куба рассчитывается один раз и кэшируется.
- Горячий UV-рендер больше не создаёт массивы позиций, объекты UV и временные векторы для каждой грани в каждом кадре.
- Маски частей, которыми управляет Emotecraft, кэшируются по комбинации головы, корпуса и конечностей. Тяжёлая модель Fresh Moves больше не обходится целиком каждый кадр эмоции.
- Видимые пользовательские части EMF кэшируются и не извлекаются повторной рефлексией каждый кадр.
- Нулевой сброс BendyLib выполняется один раз после анимации или перед отрисовкой следующей сущности, а не на каждом последующем кадре покоя.
- Состояния исчезнувших из отрисовки сущностей автоматически удаляются через минуту; длительные игровые и Flashback-сессии больше не накапливают UUID и снимки поз без ограничения.
- Проверка индивидуальной галочки типа сущности кэшируется по `EntityType`; строковый ID больше не создаётся заново для каждой сущности в каждом кадре.

## Обязательная регрессия

- обычные модели без ресурспаков;
- FA Player + Just Expressions + Emotecraft;
- Expressive Fresh Moves + Emotecraft;
- броня, инвентарь и первое/третье лицо;
- мобы, жители, лодки и вагонетки;
- Flashback и экспорт;
- все глобальные режимы FPS и выключенный эффект.
